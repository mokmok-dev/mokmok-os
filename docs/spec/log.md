* **Change**: The endpoint credential comes from the value of the environment variable `env_key` names. The file key `provider_credential_file` and its `--provider-credential-file` flag are gone with the path key, the mode 0600 check, and the write-grant check they needed, and resolution answers the name into a `Credential` that `ProviderSettings` holds and the provider is handed. `env_key` holds a bare variable name and is read literally, so it takes no `$NAME` reference, the named variable's value is trimmed, and a value that is empty or whitespace-only is refused as an unset one. The two refusals a file already had are joined by the same pair plus a not-a-name variant for each surface, and only the winning name is answered, because a flag beats the file. The kernel concept's credential invariant became two, its owned state and test paragraph were rewritten, and every citation the change moved in `config.rs` and `provider.rs` was re-derived. The decision register records the reversal and what it costs, the provider credential is no longer a file path anywhere in the examples or the NixOS module, and the two cases the change earns are a credential the stub endpoint received and a credential a confined tool did not.
